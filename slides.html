The Problem

Digital Amnesia vs. Vector Pollution

✕ Digital Amnesia (Vanilla Chatbots)

Closing the tab or restarting the app wipes all user preferences, past decisions, and project context. Every conversation starts from zero.

⚠ Vector Pollution (Naive Top-K RAG)

Dumping every conversation turn into a vector DB creates severe conflicts. If user liked Java on Day 1, then switched to C++ on Day 3, vector search retrieves both with 90%+ similarity, confusing the LLM.

💡 Core Insight: AI needs an active Memory Lifecycle Engine, not just a static search index!
Hackathon Track Rules

100% Rule Compliance Architecture

1. Cross-Session Persistence

App reboots never wipe memory. Data stored persistently on disk in SQLite vector database.

2. Live Contradiction Handling

Detects opposing facts (Java ➔ C++). Supersedes old facts to history and elevates new facts to active status.

3. Beyond Top-K Retrieval

Structured lifecycle states: ACTIVE, SUPERSEDED, FORGOTTEN, EXPIRED.

4. Grounded Provenance

Every AI response includes clickable evidence badges linking the exact memory ID and source conversation turn.

Core Intellectual Property

Deterministic Memory Lifecycle Matrix

Decision Trigger Condition System Action
CREATE New fact discovered Save as ACTIVE (v1). Compute and store embedding vector.
SUPERSEDE Contradiction on same predicate & scope (Java ➔ C++ for DSA) Mark old as SUPERSEDED. Activate new as ACTIVE (v2). Log audit trail.
SCOPE REFINEMENT Different context scope (C++ for DSA vs Python for ML) No conflict! Both coexist as ACTIVE under separate scopes.
REINFORCE User reaffirms existing fact Increment confidence score (+0.05) without duplicate vectors.
FORGET User explicitly requests removal Mark memory FORGOTTEN and quarantine from future queries.
